 To determine the total number of bytes different between two drives, you can use a tool such as `dcfldd` (Disk Copy Forensic Lite) or `rsync` with the `--checksum` option. Here's a step-by-step guide for using `rsync`:

1. First, synchronize the clone drive to the original (this will only transfer files that are different):

```bash
rsync -a --checksum --progress /path/to/source /path/to/destination
```

2. The `--checksum` option causes `rsync` to calculate an MD5 checksum for each file and only transfer files that have a different checksum, indicating a difference between the source and destination files. To get the total number of bytes transferred during this process, look at the `total size received` line in the output:

```bash
sent 120 bytes  received 450364 bytes  398328.17 bytes/sec
total size is 450364  speedup is 0.37  (written 0  read 450364  skipped 0  fast-rename 0)
```

In this example, the total number of bytes different between the source and destination is 450,364 bytes.

Alternatively, you can use `dcfldd` which provides similar functionality:

1. Start by comparing the two drives:

```bash
dcfldd if=/dev/source_device of=backup.dd ifconv=sync
dcfldd if=/dev/clone_device of=compare.dd ifconv=sync
diff compare.dd backup.dd > differences.txt
```

2. The `diff` command will produce a file called `differences.txt`, which contains the list of blocks that are different between the source and clone drives. To calculate the total number of bytes different, you can use the following command:
